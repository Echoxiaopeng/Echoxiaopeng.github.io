## 原文摘要翻译

我们提出一种用于语言-图像预训练的简单成对 Sigmoid 损失（SigLIP）。与采用 softmax 归一化的标准对比学习不同，sigmoid 损失只作用于图像-文本对，并且不需要为了归一化而对成对相似度做全局视角的计算。该损失既允许进一步放大 batch size，又在较小 batch size 下表现更好。结合锁定图像微调（Locked-image Tuning），我们仅用四块 TPUv4，在两天内训练出在 ImageNet 零样本准确率达到 84.5% 的 SigLiT 模型。由于损失定义与 batch size 解耦，我们还能研究“样本数相对对数”“负正样本比”等影响。最后，我们将 batch size 推到极端，最高至一百万，并发现继续增大 batch 的收益很快饱和，更合理的约 32k 已足够。我们在 https://github.com/google-research/big_vision 发布模型，并希望该研究推动语言-图像预训练在质量与效率上的进一步探索。

## 创新点

1. **把图文对比从“批内多类 softmax”改写成“全体配对的独立二分类”**：每对用带标签的对数 sigmoid，不再做跨整批归一化，因而也不需要为稳定 softmax 再扫一遍全局最大值。
2. **显式解耦“任务定义”与批大小**：当前批只是采样负对的方式，不再通过归一化分母进入损失语义；这让作者能系统做负正样本比、样例数对数等消融。
3. **面向数据并行的分块实现**：本地只物化局部批大小平方量级的相似度块，通过跨设备轮换文本表征覆盖全部负对，再跨设备求和；峰值显存从全局批平方降到单卡局部批平方，支撑少芯片、大全局批（直至一百万）。
4. **可学习偏置校正负样本先验**：温度取指数参数化，默认温度参数为 $\log 10$、偏置为 $-10$，避免训练初期被海量负对主导而过校正。
5. **给出资源可及的训练配方与饱和结论**：锁定图像配方四芯片两天达到 84.5%；并实证约三万二千往往接近最优，盲目冲更大批未必划算。

## 一句话总结

本文方法用成对 sigmoid 对比损失替换 CLIP 式批内 softmax，既简化分布式实现、降低峰值显存，又在小批上更强，并证明图文对比预训练通常在约三万二千批大小附近收益已接近饱和。

## 研究问题

双塔对比路线把匹配图文对拉近、非匹配对推远，主流实现是批级 softmax：对每个图像（再对每个文本）在整批相似度上做归一化。工程上至少有三处痛点：

1. **全局依赖**：归一化需要“看见”整批两两相似度；数据并行时常要全局收集全部嵌入，并物化全局批平方量级矩阵。
2. **数值稳定**：朴素 softmax 需先减全局最大值，等于再扫一遍整批。
3. **语义与规模耦合**：负样本集合由当前批决定，批大小既影响优化噪声，也直接改变“分类题”的类数。

论文的问题因此很具体：能否用**不依赖全局归一化**的成对目标，在保持（甚至提升）零样本质量的同时，让损失计算更省内存、更易扩展，并借此把批大小从“必须越大越好”的教条里拆出来重新测量。

## 数据与任务定义

### 训练配方三件套

| 配方 | 图像塔 | 文本塔 | 数据 | 要点 |
|---|---|---|---|---|
| SigLiT | 冻结 / 预计算嵌入（如公开 ViT） | 从零训练 | LiT 图文数据 | 对齐锁定图像微调；便于把全局批推到极端 |
| SigLIP | 中等 ViT，可从零或解锁微调 | 同规模文本塔 | WebLI 英语对 | 对标双塔联合训练 |
| mSigLIP | 同 SigLIP | 多语词表（可加瓶颈嵌入） | WebLI 约百种语言 | 评测侧重跨语检索基准 |

### 输入与评测

- **图像**：主设定常为 $224\times 224$；放大实验用更多图像块并加长文本序列。
- **文本**：英语设定用约三万二千词表；多语比较小词表与二十五万词表，大词表可用瓶颈投影省嵌入显存。
- **主指标**：ImageNet 零样本分类；跨语检索基准上三十六语种图文双向召回。
- **优化器默认**：大批训练时将二阶动量系数从 0.999 降到 0.95 以抑制梯度尖峰。

## 方法主线

### Softmax 对比损失（基线）

- **问题**：需要在整批上分别做“图到文”与“文到图”两次归一化，嵌入需二范数归一化，并用可学习温度缩放点积。
- **方法**：对匹配对最大化对应方向的对数 softmax；非匹配对进入分母。
- **具体实现**：数据并行下通常全局收集全部嵌入，再算满矩阵；显存与通信随全局批大小二次上升。

### Pairwise Sigmoid 损失（SigLIP）

- **问题**：去掉全局归一化，同时处理“负对远多于正对”的类别先验。
- **方法**：把学习问题改写成全体配对上的二分类。先算带温度与偏置的配对打分，再用正负标签做对数 sigmoid（与算法一一致）：

$$
\mathcal{L}=-\frac{1}{|B|}\sum_{i=1}^{|B|}\sum_{j=1}^{|B|}\log\sigma\bigl(z_{ij}\,(t\,x_i\cdot y_j+b_{\mathrm{bias}})\bigr)
$$

- $x_i,y_j$: 图像 / 文本二范数归一化嵌入
- $t=\exp(t')$: 可学习温度（由 $t'$ 参数化）
- $b_{\mathrm{bias}}$: 可学习打分偏置，用于近似负多正少的先验；默认初始化为 $-10$
- $z_{ij}$: 配对标签，匹配为 $+1$，否则为 $-1$
- $\sigma$: sigmoid；实现对全体配对项求和后除以全局批大小（按“每图像”平均）

伪代码要点（算法一）：先对归一化嵌入做带温度与偏置的点积矩阵，对角为正、其余为负，再对带标签打分做对数 sigmoid 并按批大小平均。

初始化上，偏置取 $-10$ 且温度参数取 $\log 10$ 在多项零样本分类上全面最好；无偏置或偏置取零并搭配过小温度会明显崩溃（例如 ImageNet 零样本掉到 53.7）。直觉是：训练一开始打分应接近“几乎全是负对”的先验，否则早期梯度会猛烈过校正。

### Chunked 分布式实现

- **问题**：即便损失可分解，若仍在单卡物化全矩阵，大 $|B|$ 仍不可行。
- **方法**：记全局批大小、设备数与每卡局部批。图像块留在本机，文本块在设备间轮换；每步只算当前局部块上的正负对损失并累加，最后跨设备求和。
- **具体实现**：先算含本地正对的块，再轮换邻居文本块覆盖其余负对；任意时刻内存主项是局部批平方而非全局批平方。论文指出多次集体轮换往往仍快于两次跨设备全局收集。

### 机制流程

1. **输入**：每卡本地图像嵌入，以及当前分片上的文本嵌入（初始为与本地图像配对的那一片文本）。
2. **操作**：二范数归一化后做带温度与偏置的点积；对正对角与负非对角累计对数 sigmoid 损失；把文本嵌入轮换到下一设备并重复，直到覆盖全部文本分片。
3. **输出**：各设备局部损失求和得到全局标量；反向传播更新双塔（锁定图像设定下图像塔冻结，只更新文本塔）。

### 符号说明

| 符号 | 含义 |
|---|---|
| $\|B\|$ | 全局图文对批大小 |
| $b$ | 每设备局部批大小 |
| $t,t'$ | 温度及其无约束参数，$t=\exp(t')$ |
| $b_{\mathrm{bias}}$ | 打分偏置（论文符号为 $b$，与每卡局部批同名；此处加下标以避免混淆） |
| $z_{ij}$ | 配对标签 $\pm 1$ |

### 消融到底说明了什么

1. **偏置项（表 4）**：不是可有可无的小技巧；它直接服务“负多正少”先验，和温度初始化绑定。
2. **负正样本比（图 6，正文叙述）**：随机丢掉负对会掉点；只留 easy negatives 几乎学废；hard negatives 能大致保住质量，匹配总对数后再训更久略好。结论是：**类别不平衡本身未必是主凶，但如何高效纳入更多难负例仍开放**。
3. **大 batch 稳定（图 5）**：不稳定性来自梯度范数尖峰 → 权重猛跳；$\beta_2=0.95$ 让优化器更快忘掉尖峰，成为默认。
4. **标签噪声（图 7）**：对图像噪声、文本随机记号、批内对齐打乱及其组合，sigmoid 曲线更抗噪，契合网页图文天然很脏的设定。

### 失败或不稳定设置

- 超大 batch + 默认 $\beta_2=0.999$：loss / 梯度尖峰可毁掉训练。
- 解锁微调却保留图像塔 weight decay：零样本与线性探测双崩。
- 多语 batch ≫32k：ImageNet 仍平坦，但 XM 平均与部分语言（如中文）明显下滑。
- 温度过小且偏置初始化不当：早期优化路径错误，后期难救。

## 深度分析

### 为什么有效

批内 softmax 对比把每个锚点做成多类分类，小批时负类集合又窄又吵，归一化分母估计差。成对 sigmoid 把每对当成独立评分，**小批不再被迫用很差的多类归一化**；这与分类任务里 sigmoid 有时更稳的旧观察同向。可学习偏置则把“绝大多数对应为负”写进初始化，避免第一步就被负例海淹没。

Chunked 实现的收益是工程性的但决定了论文能否把 batch 轴扫完整：没有它，1M 与“四芯片装更大 batch”的故事讲不成。性能饱和则说明：**对比学习吃的是有效难负例与足够更新步数，不是名义负例个数的无限上升**；多语结果更表明“同语言难负例”假说不能简单用加大全局 batch 代替。

### 复杂度与扩展性

- **计算**：仍需覆盖约 $|B|^2$ 量级配对项，但可分块；通信模式从 all-gather 全嵌入转为多次 permute 文本块。
- **显存**：峰值相似度从 $|B|^2$ 降到 $b^2$，而扩展全局 batch 常靠加卡、保持 $b$ 近似常数。
- **扩展边界**：从零训更大模型、更长上下文、更高分辨率时，其他激活显存会重新占主导；sigmoid 主要解放的是**损失矩阵**这一项。

### 复现注意点

1. 温度与偏置初始化按 $t'=\log 10$、$b=-10$；不要随手把偏置设 0。
2. 大 batch 把 $\beta_2$ 降到 0.95；观察梯度范数尖峰是否被快速消化。
3. 微调公开 ViT 时：图像塔小 LR、关 WD；文本塔正常衰减。
4. 先用约 32k 做主设定，再决定是否为吞吐或特定数据混合冲更大 batch。
5. 权重与实现参考 `big_vision`；完整 WebLI / LiT 私有数据通常不可原样重训，公开对比应优先加载发布检查点。

## 局限

1. **数据不可完全公开**：主结论绑定 LiT / WebLI 配方；外部复现多依赖发布权重，而非端到端数据重跑。
2. **公开表 3 非严格对照实验**：分辨率、训练预算、架构变体纠缠，展示的是发布模型竞争力，不是单一损失替换的因果效应。
3. **百万批设定主战场在锁定图像配方**：冻结图像塔并预计算嵌入，不能直接外推为从零联合训练在同样全局批下的最优性。
4. **“32k 足够”是经验饱和点**：换数据混合、模型尺度、词表与分辨率后仍需重测；多语上更大 batch 已给出反例。
5. **负对无关假设本身有噪声**：论文用合成腐蚀证明更鲁棒，但不等于清洗后的监督信号可被替代。

## 我的笔记

- 若你在少卡上复现开放 CLIP：优先试 sigmoid + chunked，并把默认 batch 锚在 16k–32k，而不是一上来堆到 100k+。
- 把“损失是否需要全局归一化”当成系统设计问题：很多后续开放实现（含社区 SigLIP 权重）吃的就是这条简化。
- 负样本研究可以站在这篇的肩膀上：hard-negative mining / 跨 batch 队列若能在通信预算内做，仍可能挖潜。
- 后续阅读可对照 LiT、FLIP、OpenCLIP、以及采用 SigLIP 损失的开放复现与更大规模后续工作。
